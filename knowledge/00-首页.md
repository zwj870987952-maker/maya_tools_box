这个项目目录同时可以作为 Obsidian Vault。源代码、规范和知识笔记位于同一个仓库，Obsidian 不保存另一份代码副本。

## 首次在 Obsidian 中打开

在 Obsidian 的 Vault 选择界面选择“打开本地文件夹作为仓库”，选择整个 maya_tools_box 项目目录，而不是只选择 knowledge 子目录。这样知识笔记才能链接到同一 Vault 中的源码和规范。

## 保持同步

在 PowerShell 中运行：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\knowledge\启动实时同步.ps1
~~~

脚本会先生成一次知识库，再在后台监听源码和文档变化。Obsidian 打开此 Vault 时会显示更新后的 Markdown 文件。重新登录电脑后，可再运行一次启动脚本；重复运行不会启动第二个监视进程。

如果已有 Python 3.7+，也可只运行一次生成器：

~~~powershell
python .\scripts\sync_obsidian_knowledge.py
~~~

如果系统没有普通 Python，启动脚本会寻找本机 Codex 捆绑的 Python 或 Maya 2022+ 的 mayapy。

## 登记已验证的组合

在 Maya 中确认两个正式工具可以按顺序协作后，先在 `docs/tools/` 写明输入、输出和验证步骤，再将它们登记到 `knowledge/relations.json`。登记后，关联页与工具卡会在下一次同步时更新。尚未验证的想法可写在个人笔记中，不计入“已验证功能组合”。

## 数据来源与编辑规则

- knowledge/_generated/ 中的页面由脚本生成，**不要手工修改**；下次同步会覆盖生成页。
- 正式工具信息来自 maya_toolkit/tools/ 下的静态类元数据及参数 Schema；生成时不会导入或运行 Maya 代码。
- 待整理工具来自实际目录，描述优先取 tools_staging_pool/README.md。未登记目录会列在规模评估页。
- 代码关联来自静态 import，不能等同于已验证的功能组合。实际功能、Maya 直验和可组合流程应写在 docs/tools/ 的专项知识说明。
- 经 Maya 验证的跨工具调用链可登记在 knowledge/relations.json，包含前后工具 ID、组合理由与说明文档路径；未登记的相似性只作结构线索。
- Obsidian 内可以自由新增个人笔记；放在 knowledge/_generated/ 之外即可避免被生成器覆盖。
